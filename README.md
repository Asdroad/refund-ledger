# Refund Ledger

Леджер возмещений для маркетплейса: удерживает деньги с продавца, выплачивает покупателю и не платит дважды, когда провайдер молчит, воркер упал, а сообщение пришло повторно.

**Стек:** .NET 10, gRPC, Kafka, PostgreSQL, Redis, OpenTelemetry (Jaeger, Prometheus, Grafana), Graylog, Helm, GitLab CI.

## Как это работает

```
сервис возвратов ──Kafka──► Worker ─┐                ┌─► Kafka (outbox)
                                    ├─► PostgreSQL ──┤
клиенты ──────────gRPC────► Api ────┘                └─► провайдер выплат
```

Путь возврата на 1 000 ₽, если у продавца есть 600 ₽:

| Шаг | Дебет | Кредит |
|---|---|---|
| Начисление | продавец 600, расход маркетплейса 400 | покупатель 1 000 |
| Резерв под выплату | покупатель 1 000 | в пути 1 000 |
| Провайдер подтвердил | в пути 1 000 | расчёты с провайдером 1 000 |
| *или* провайдер отказал | в пути 1 000 | покупатель 1 000 |

Статусы выплаты:

```
Pending ──► Sending ──► Succeeded
   ▲           │  └───► Rejected ──(ручной повтор)──► новая выплата
   │           ▼
   └──────  Unknown ──► Succeeded / Rejected
```

`Unknown` — главный статус. Таймаут не отказ, поэтому деньги ждут на счёте «в пути», пока провайдер не даст ответ.

## Запуск

```bash
docker compose up -d --build
```

| Что | Где |
|---|---|
| gRPC | `localhost:5001` |
| Заглушка провайдера | `localhost:5080` |
| Jaeger | http://localhost:16686 |
| Grafana | http://localhost:3000 |

Включить сбои провайдера (`ok`, `decline`, `throttle`, `error_before`, `error_after`, `hang_after`, `chaos`):

```bash
curl -X POST localhost:5080/admin/mode/chaos
```

Graylog поднимается отдельно: см. [docker-compose.graylog.yml](docker-compose.graylog.yml). Нагрузка: `k6 run load/k6/refunds.js`.

## Замеры

Общий счёт `in_transit` меняет каждый возврат. Сравниваются блокировка его строки (`strict`) и очередь дельт (`delta`), см. [ADR 002](docs/adr/002-balance-modes.md).

| Потоков | strict, возвратов/с | delta, возвратов/с | strict p99, мс | delta p99, мс |
|---|---|---|---|---|
| 1 | 307–321 | 279–289 | 6–7 | 10 |
| 8 | 505–540 | 895–933 | 49–65 | 18–22 |
| 32 | 310–323 | 620–633 | 701–764 | 173–203 |

Без конкуренции дельты на 6–13 % медленнее, под конкуренцией дают 1,7–2 раза выигрыша. На 32 потоках просели оба режима; причину я не выяснял.

Страница журнала на глубине 149 000 (журнал 300 000 строк): `OFFSET` — 107 мс, курсор — 0,6 мс.

Условия: ноутбук Apple Silicon с 8 ядрами и 8 ГБ, PostgreSQL 14 на нём же, по два прогона на режим по 6 секунд, машина была занята и другими задачами. Верить стоит отношению, а не абсолютным цифрам. Повторить:

```bash
dotnet run -c Release --project tools/RefundLedger.Bench -- "Host=localhost;Username=ledger;Password=ledger;Database=postgres" 10 1000000
```
