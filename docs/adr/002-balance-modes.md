# 002. Строгие остатки и очередь дельт

**Проблема.** Каждый возврат меняет общий счёт `in_transit`. Если обновлять его строку в той же транзакции, все возвраты встают в очередь за одной блокировкой.

**Решение.** У счетов два режима:

- `strict` — продавец и покупатель. Есть порог, остаток меняется сразу.
- `delta` — общие счета. Порога нет, транзакция только вставляет дельту, а фон сворачивает её в остаток.

Точный остаток в любой момент: `balance_minor + sum(дельт)` одним запросом, то есть в одном снимке.

**Почему не «водяной знак» по id.** id выдаётся раньше коммита. Транзакция с меньшим id может закоммититься позже, и знак пропустит её навсегда. Здесь дельта удаляется и прибавляется одним запросом, а `DELETE` видит только закоммиченное.

**Сворачивает один экземпляр** под advisory-блокировкой. Первая версия разрешала параллельные свёртки через `skip locked`, и они изредка взаимно блокировались: порядок обновления счетов внутри `update … from` не задать. Случай закрыт тестом.

**Блокировки.** Строгие счета обновляются по возрастанию id. Счёт с нулевой итоговой разницей не блокируется.

**Остаётся узким местом.** Возвраты одного продавца идут последовательно: доля продавца зависит от его остатка.
