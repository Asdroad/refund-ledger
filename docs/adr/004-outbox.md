# 004. Outbox, at-least-once и порядок событий

**Решение.** Событие пишется в `outbox` той же транзакцией, что и деньги. Публикатор отправляет и только потом удаляет: сбой между шагами даёт дубль, но не потерю.

**Порядок.** Публикует один экземпляр под advisory-блокировкой. Ключ сообщения — id возврата. При частичном сбое пачка уходит заново целиком, поэтому порядок дублей не гарантирован. В событии есть `eventId` для отсева дублей и `version` для отсева устаревших.

**Входящие.** Inbox не нужен: `RegisterRefund` идемпотентен по id возврата. Смещение сохраняется после записи в БД. Битые сообщения уходят в DLQ, временные сбои повторяются с паузой.

**Почему не exactly-once Kafka.** Её транзакции не охватывают PostgreSQL.

**Осознанный компромисс.** На время отправки публикатор держит одну транзакцию. Она единственная и ограничена `MessageTimeoutMs`.
